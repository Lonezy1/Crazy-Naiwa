【开始前先核对】
1. 先检查当前项目的 Godot 版本、project.godot、主场景、节点树、代码结构、Git 状态和已有测试。不要假设项目等于本模板，也不要覆盖或还原用户已有修改。
2. 先按数据链路理解功能：输入/信号 -> 行为状态 -> 窗口或角色表现 -> 需要时保存设置。基于实际调用关系判断模块边界；小而清楚的功能可留在现有脚本，只有职责独立、可测试或已形成明显复杂度时才新增文件。
3. 动手前简要说明会改哪些文件、状态如何流动、是否需要持久化和自动化测试。用户要求直接实现时，不要只给方案。

【Godot 桌宠窗口规则】
1. 必须区分项目设置 `window/subwindows/embed_subwindows` 与编辑器的 Game Embedding / Embed Game on Next Play。前者不能关闭后者；后者是编辑器设置，通常不随 Git 项目或 ZIP 一起分发。
2. 桌宠移动需要实际的独立 OS 窗口。屏幕坐标下移动主窗口使用 `DisplayServer.window_set_position(Vector2i(x, y), 0)`；读取系统鼠标/窗口位置使用对应的 `DisplayServer` API。局部视口坐标与桌面屏幕坐标不可混用。
3. `DisplayServer.window_set_position()` 不能绕过 Godot 对嵌入式游戏窗口的限制。若 F5 游戏仍嵌在编辑器，指导我关闭 Game Embedding 或用 `godot --path <项目目录>` 启动主场景；不要每帧重试并刷屏。只有需求明确要求“嵌入和独立两种模式都支持”时，才增加有明确行为的嵌入模式分支。
4. 设置无边框、透明、置顶与窗口移动是不同职责。鼠标穿透用 `get_window().mouse_passthrough_polygon`，根据实际角色命中轮廓配置，并验证不影响点击、拖动和右键菜单。
5. 修改输入后验证按下、移动、松开完整状态链；注意 Godot 的 viewport 坐标与 `DisplayServer` 屏幕坐标转换，以及窗口原点偏移。

【维护与质量规则】
1. 先复用项目已有主题、颜色、字体、菜单和控件模式，不无故增加颜色、卡片或装饰。
2. 判断是否新增文件、提取模块、重写或删除旧格式。除非确有行为/复杂度理由，不重写已有系统、不制造空抽象。用户明确不保留旧格式时，删除失效兼容代码，但保留原始素材和用户数据。
3. 持久化按需求决定。少量本地偏好用 `ConfigFile` 存入 `user://`；不需要跨设备同步时不要引入数据库。不要把运行缓存、机器专属编辑器偏好或生成文件提交到 Git。
4. 自动化测试按风险添加：纯逻辑用 headless 测试；场景结构和资源引用做 smoke test；透明、鼠标穿透、窗口移动、置顶等必须再做 Windows GUI 独立窗口实测。不要声称 headless 测试覆盖了系统窗口行为。
5. 完成后运行相关测试、Godot 导入/解析、`git diff --check`，总结实际验证结果与未能验证的部分。只在我要求时推送/发布；发布时同步更新版本号。

【初学者桌面验证步骤】
在 Godot 顶部 Game 设置中关闭 `Embed Game on Next Play`，停止当前运行实例后按 F5。若仍看到嵌入编辑器的棋盘格/游戏面板，那不是独立桌宠窗口；先确认 Game Embedding 状态，再测试系统窗口拖动。项目里的 `Embed Subwindows` 不是这个开关。
